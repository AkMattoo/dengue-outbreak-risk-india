Forecasting dengue outbreak risk
across Indian states

A probabilistic early-warning model built on India's IDSP outbreak surveillance records (2009–2022), with walk-forward validation and an honest account of what the data can and cannot support.

Data Science Intern · Technical Assignment Python · scikit-learn · LightGBM 3,696 state-months

The problem the data actually supports

The obvious task — forecast dengue case counts — is not answerable with this data, and discovering that was the first real finding.

EpiClim packages IDSP records as an event log: one row per reported outbreak, not routine surveillance counts. It holds 1,698 dengue records across 345 districts and 14 years, a median of three records per district. A district-week forecasting model needs hundreds of observations per district.

Aggregated to state × month, the data becomes a complete, modellable grid. So the question was reframed to one the data can answer: will state S report a dengue outbreak in month t+h? — a probabilistic classification problem at horizons of 1, 2 and 3 months.

The headline finding is not the one you would expect

The simple baselines beat the machine learning. Smoothed climatology wins at one month ahead; at two and three months the plain state base rate — which ignores seasonality entirely — wins outright. LightGBM never leads.

This is reported rather than buried, because it says something real: outbreak reporting is driven mainly by which state you are looking at, not by season or recent history. The model is substantially learning which states have strong surveillance. That is the reporting-bias problem showing up quantitatively.

Method

  • Target — binary outbreak occurrence, 1/2/3 months ahead.
  • Features — outbreak history (lags 1–12, rolling means, months since last outbreak); expanding state × month climatology; sin/cos seasonality and monsoon flags; a COVID-year flag; log population and density.
  • Baselines — seasonal climatology, empirical-Bayes smoothed climatology (α = 10, because raw state × month cells rest on ~10 observations each), persistence, and state base rate.
  • Models — LightGBM with small trees, and logistic regression as a transparent, well-calibrated reference suited to ~3.7k rows.
  • Validation — walk-forward with an expanding window over the final three years, giving several independent out-of-sample years rather than one. A unit test corrupts all data from a cutoff onward and asserts that no earlier feature value changes, proving the absence of lookahead leakage.

Limitations

  • Reported outbreaks are not outbreaks. A zero means nothing was reported. The target partly measures surveillance capacity rather than disease burden.
  • Presence-only data — negatives are assumed, never observed.
  • Occurrence is not burden — one reported outbreak may be 5 cases or 15,000.
  • State aggregation loses spatial detail, but district level is far too sparse.
  • Climate features were implemented but not run. src/fetch_climate.py integrates the Open-Meteo archive; lagged rainfall and temperature remain the most promising unused predictors.
  • Census 2011 population is increasingly stale across a 2009–2022 window.
  • Associational, not causal.

Next steps

  • A two-stage hurdle model for outbreak size conditional on occurrence.
  • Explicitly modelling per-state reporting propensity, to separate surveillance from disease.
  • Spatial spillover features from neighbouring states.
  • Parsing IDSP weekly PDFs directly to recover finer temporal resolution.
